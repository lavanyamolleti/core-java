Java:
	1. Composition-part of- strong association. Any changes that you perform in one component it will be highly affecting another component(high coupling)
	2. Aggregation-part of- weak association. Any changes that you perform in one component it will NOT be highly affecting another component(loose coupling)

Constructor Injection:
	Dependencies injected using constructor are called as mandatory dependencies
    <constructor-arg value="Udhay"></constructor-arg>
    <constructor-arg value="3000.0"></constructor-arg>
    <constructor-arg ref="skill"></constructor-arg>
Dependencies are injected based on order of the datatypes present in the constructor(String, Double, Skill)

If parameters compose of non implicit reference datatype only then the order of the arguments does not matter

class Employee{
	Address address;
	Contact contact;
	Employee(Address address, Contact contact){
		..
	}
}
Both the below definitions works fine.

<bean id="emp" class="Employee">
    <constructor-arg ref="address"></constructor-arg>
    <constructor-arg ref="contact"></constructor-arg>
</bean>

<bean id="emp" class="Employee">
    <constructor-arg ref="contact"></constructor-arg>
    <constructor-arg ref="address"></constructor-arg>
</bean>

Dependencies are injected based on order of the datatypes present in the constructor(String, Double, Skill)
	If i change the order I will get UnsatisfiedDependencyException
(1) Resolve this issue by providing type attribute
(2) index attribute can be provided to specify the order of constructor argument(It starts from 0)
(3) name attribute can be provided

Mixed DI
--------
	Constructor and setter dependency can be used together while creating the beans
	Constructor based DI - mandatory or immutable dependencies
	Setter based DI - optional or mutable dependencies
	Constructor based DI happens first followed by setter based
